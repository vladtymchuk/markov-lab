# План і методологія тестування

Мета полягає в перевірці математичної коректності, відтворюваності даних та шляху користувача. Одномодульний та тримодульний еталони мають незалежні замкнені розв’язки. Hypothesis варіює r, λ і горизонт, включно з нулем та межами імовірностей. Seeded Монте-Карло перевіряється на двох типах ланцюгів. Імовірнісна перевірка використовує фіксований seed і доповнює детерміновані еталони.

| Рівень | Метод | Критерій |
|---|---|---|
| Математичні еталони | pytest, NumPy | Відомі розподіли, поглинання, самовиклики, старт у момент 0 |
| Генеративні перевірки | Hypothesis | Невід’ємність, сума 1, монотонність R |
| Інтеграція | TestClient і PostgreSQL | Схема Alembic, транзакції, конфлікт версії, знімок та експорт |
| Компонентний UI | Vitest і Testing Library | Помилка порожньої назви, очищення введення, передавання форми |
| Наскрізний | Chromium і Playwright | Створення, редагування P, сценарій, аналіз, файли, повторне відкриття, мобільна навігація |
| Збірка | TypeScript, ESLint, Ruff, mypy, Next.js, Compose | Збірка й старт до робочого HTTP API та вебінтерфейсу |

PostgreSQL для тестів має використовувати окрему базу. CI піднімає чистий сервіс. Playwright створює тестовий проєкт і видаляє його після випадку. Вихідні імовірності порівнюються з допусками в [описі методів](mathematical-models.md). Див. [ідентифіковані кейси](test-cases.md) та [протокол](test-results.md).
